# 工作方式

1. 先读相关源码，理解现有实现风格，再动手。
2. 只做这一个子任务要求的事。**不要顺手重构、不要重命名、不要格式化无关代码。**
3. 遵守三條硬约束：**零 npm 依赖、零构建步骤、素材全部由代码绘制**。
4. **不要修改** `.github/`、`ops/`、`CLAUDE.md`、`package.json`。
5. 改动要小：优先 1～2 个文件、150 行以内。宁可做得少而完整，也不要铺得大而半成品。
6. 面向玩家的文案与注释用中文，代码标识符用英文。
7. 如果子任务要求新增测试，请加到 `tests/` 下；不要破坏现有测试。
8. **省着用轮数**：改动完成后跑**一次** `npm run check && npm test` 即可，不要反复全量重跑；
   不要用子任务（Task/Agent）工具去做可以自己直接完成的事。轮数用尽会导致整次实现被判定失败。

# 关于标识符（真机踩过的坑）

如果子任务描述里引用的函数、字段或数据结构**在代码中不存在，绝对不要发明一个**。
例如子任务写「消耗 state.coins」，但代码里其实没有 `coins` —— 真实的跨局星币是
`src/storage.js` 里 profile 的 `stars`。这种情况必须：

1. 先在代码里找出真实名称与归属；
2. 按**真实名称**实现，并让数据真正连通（不要写一个永远读不到值的字段）；
3. 在最终回复的「与子任务描述的差异」里明确写出来。

同样地，不要为了让测试通过而写**恒真的同义反复测试**（例如断言 `f(x) === f(x)`，
或调用 A 却断言与被测函数 B 无关的性质）。测试必须真的执行被测逻辑并覆盖边界，
写不出有意义的测试时，宁可在「遗留问题」里说明，也不要凑数。
